# CV0008: Closed value declares a generated member

## Cause

The closed value type declares a member with the name of a member that the generator writes:

| Name | Generated when |
|---|---|
| `All`, `allInstances`, `FromName`, `TryFromName`, `ClosedValueTypeConverter`, `ClosedValueJsonConverter`, `ClosedValueEfCoreConverter` | Always. |
| `Equals`, `GetHashCode`, `operator ==`, `operator !=` | Always, except in a record or record struct, where the compiler writes them and an own `Equals` is allowed. |
| `Match`, `Switch`, `Map` | The type has at least one instance. |
| `TryParse`, `Parse` | The type has a key, or the project uses C# 11 or later on .NET 7 or later, where the generator implements `IParsable<T>`, unless `Parsable` is switched off. |
| `implicit operator`, `explicit operator` | The type has a key: a property with `[ClosedValueKey]`, or exactly one member of a basic type. |
| `CompareTo`, `operator <`, `operator <=`, `operator >`, `operator >=` | The key is a basic type other than `bool` or `string`. |

## Rule

Two members with the same name give a compiler error that points at the generated code. This rule names the
member in your code instead.

`ToString()` is not on the list. When you declare it, the generator skips its own. `ValidateConstructorArguments`
is not on the list either: it is a partial method for you to implement.

## Fix

Rename the member.

```csharp
public static IEnumerable<Color> All => ...;      // CV0008
public static IEnumerable<Color> Warm => ...;     // correct
```
